### Task 2: `parseOwner` w `readRegistry` (TDD)

**Pliki:** `contexts/bc_projects/repositories/index.ts`, test `tests/unit/contexts/bc_projects/repositories.test.ts`.

Reguły (spec D2): `undefined`/`null`/tekst pusty po `trim` → `personal`; tekst dokładnie `personal` lub `work` po `trim` → ta wartość; wszystko inne → `work` plus ostrzeżenie. Wartość nietekstowa (lista, mapa) nie przechodzi przez `text()` i w komunikacie jest `(nie tekst)`; liczba i bool dostają `String(raw)`.

- [ ] **Step 1: Testy** w `repositories.test.ts` (nowy `describe("readRegistry: owner")` pod istniejącym; używa `vault.write(REGISTRY, …)`). Pomocnik w pliku:

```ts
function registryWithOwner(ownerLine: string | null): string {
  return [
    "projects:",
    "  - id: a",
    "    folder: Projects/a/",
    ...(ownerLine === null ? [] : [`    ${ownerLine}`]),
    "",
  ].join("\n");
}

const UNKNOWN = (shown: string) =>
  `Projects/_registry.yaml: pozycja 1: nieznane owner "${shown}", traktuję jako work`;
```

Przypadki (`const r = readRegistry();` po `vault.write(REGISTRY, registryWithOwner(<linia>))`; sprawdzaj `r.entries[0].owner` i `r.warnings`):

| Linia w YAML                           | `owner`    | `warnings`                 |
| -------------------------------------- | ---------- | -------------------------- |
| (brak pola: `registryWithOwner(null)`) | `personal` | `[]`                       |
| `owner: personal`                      | `personal` | `[]`                       |
| `owner: work`                          | `work`     | `[]`                       |
| `owner: ""`                            | `personal` | `[]`                       |
| `owner:` (null)                        | `personal` | `[]`                       |
| `owner: " work "`                      | `work`     | `[]`                       |
| `owner: Work`                          | `work`     | `[UNKNOWN("Work")]`        |
| `owner: firma`                         | `work`     | `[UNKNOWN("firma")]`       |
| `owner: true`                          | `work`     | `[UNKNOWN("true")]`        |
| `owner: 1`                             | `work`     | `[UNKNOWN("1")]`           |
| `owner: [work]`                        | `work`     | `[UNKNOWN("(nie tekst)")]` |
| `owner: {a: 1}`                        | `work`     | `[UNKNOWN("(nie tekst)")]` |

Dodatkowy test: dwa wpisy (`a` bez `owner`, `b` z `owner: Work`): ostrzeżenie dotyczy `pozycja 2` i tylko jego.

- [ ] **Step 2: Czerwono.** `npx vitest run tests/unit/contexts/bc_projects/repositories.test.ts`: nowe przypadki oprócz tych z oczekiwanym `personal` padają.
- [ ] **Step 3: Implementacja** w `repositories/index.ts`: dopisz `Owner` do importu typów z `../models`, nad `readRegistry` dodaj:

```ts
function parseOwner(raw: unknown, n: number, warnings: string[]): Owner {
  if (raw === undefined || raw === null) return "personal";
  if (typeof raw === "string") {
    const value = raw.trim();
    if (value === "") return "personal";
    if (value === "personal" || value === "work") return value;
  }
  const shown = typeof raw === "object" ? "(nie tekst)" : String(raw).trim();
  warnings.push(
    `Projects/_registry.yaml: pozycja ${n}: nieznane owner "${shown}", traktuję jako work`
  );
  return "work";
}
```

W `readRegistry` zamień `owner: "personal"` na `owner: parseOwner(raw.owner, n, warnings)` (`n` i `warnings` już istnieją w pętli).
